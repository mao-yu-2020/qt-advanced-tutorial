## 1. 自定义委托完整实现

### 1.1 绘制 + 编辑交互委托

下面的委托在项的左边画一个 200 像素的椭圆、右边显示数据，并创建了编辑交互代理。注意编辑完成时要发射 `commitData` / `closeEditor`，否则不会走到 `setModelData()`：

```cpp
void ItemDelegate::paint(QPainter *painter,
                         const QStyleOptionViewItem &option, const QModelIndex &index) const {

    // 绘制背景
    if (option.state & QStyle::State_Selected) {
      // 被选中状态设置成红色
      painter->setBrush(Qt::red);
    } else if (option.state & QStyle::State_MouseOver) {
      // 鼠标盘旋设置为绿色
      painter->setBrush(Qt::green);
    } else {
      // 默认为黑色
      painter->setBrush(Qt::black);
    }
    // 画一个椭圆
    painter->drawEllipse(option.rect.x(), option.rect.y(), 200, option.rect.height());

    QStyleOptionViewItem opt = option;
    // 设置宽度及x轴，这里不需要减去椭圆部分的，因为默认它会减去x的坐标
    opt.rect.setWidth(opt.rect.width());
    opt.rect.setX(opt.rect.x() + 200);

    // 拿到要显示的数据
    opt.text = index.data().toString();

    // 使用qt样式进行绘制控制外形可以 样式表能生效，重点是要传入opt.widget参数
    qApp->style()->drawControl(QStyle::CE_ItemViewItem, &opt, painter, opt.widget);
}

// 交互小部件，调用顺序0
QSize ItemDelegate::sizeHint(const QStyleOptionViewItem &option,
                             const QModelIndex &/*index*/) const {
    return QSize(option.rect.width(), 200);
}

QWidget *ItemDelegate::createEditor(QWidget *parent,
                              const QStyleOptionViewItem &option,
                                    const QModelIndex &index) const {
    // 交互小部件，调用顺序1
    qDebug() << __FUNCTION__;

    // 创建一个编辑小部件
    QLineEdit* line = new QLineEdit(parent);

    // 关联小部件编辑完成时，进行提交和关闭小部件，否则的话是不会调用到setModelData函数的
    QObject::connect(line, &QLineEdit::editingFinished, this, &ItemDelegate::editFinish);
    return line;
}

void ItemDelegate::setEditorData(QWidget *editor, const QModelIndex &index) const {
    // 交互小部件，调用顺序3
    qDebug() << __FUNCTION__;

    // 设置小部件数据显示
    QLineEdit* line = qobject_cast<QLineEdit*>(editor);
    if (line)
      line->setText(index.data(Qt::DisplayRole).toString());
}

void ItemDelegate::setModelData(QWidget *editor,
                          QAbstractItemModel *model,
                                const QModelIndex &index) const {
    // 交互小部件，调用顺序4
    qDebug() << __FUNCTION__;

    // 将小部件的数据更新到模型中
    QLineEdit* line = qobject_cast<QLineEdit*>(editor);
    if (line)
      model->setData(index, line->text(), Qt::EditRole);
}

void ItemDelegate::updateEditorGeometry(QWidget *editor,
                                  const QStyleOptionViewItem &option,
                                        const QModelIndex &/*index*/) const {
    // 交互小部件，调用顺序2
    qDebug() << __FUNCTION__;

    // 设置小部件对于父部件的位置，位置信息在opiton中
    editor->setGeometry(option.rect);
}

void ItemDelegate::editFinish() {
    // 完成编辑提交数据，关闭编辑器
    QLineEdit* line = qobject_cast<QLineEdit*>(sender());
    emit commitData(line);
    emit closeEditor(line);
}
```

除了这种一般代理外，还有另一种情况是直接操作视图，比如视图是绘制一个QCheckBox或者QPushButton这种。

实际上我们知道，表格默认显示的内容其实是表格自己绘制出来的。只有在用户双击交互时才会创建一个代理交互对象，然后将位置移动到对应的显示上面。

但如果是个按钮的点击事件，就无法触发这种操作，很显然对于这种情况我们并不需要构建交互的Widget部件，因为它直接操作的是表格事件了。

对于这种情况的处理方式为，一绘制按钮的形状(paint)，二是触发按钮相关事件(editorEvent)。

以CheckBoxItemDelegate代理为例子

```cpp
#pragma once


#include <functional>

#include <QtCore>
#include <QtWidgets>

class CheckBoxItemDelegate : public QStyledItemDelegate
{
    Q_OBJECT
public:
    /// 默认处理过滤函数回调
    using HandleFilter = std::function<bool(QModelIndex)>;

    CheckBoxItemDelegate(QObject *parent = nullptr);

    void setHandleFilter(HandleFilter handle) noexcept;

    void paint(QPainter *painter,
               const QStyleOptionViewItem &option, const QModelIndex &index) const override;

    bool editorEvent(QEvent *event, QAbstractItemModel *model,
                     const QStyleOptionViewItem &option, const QModelIndex &index) override;

signals:
    void checkBoxState(bool isChecked);

private:
    HandleFilter _handleFilter;
};

```

```cpp
#include "CheckBoxItemDelegate.h"



CheckBoxItemDelegate::CheckBoxItemDelegate(QObject *parent)
    : QStyledItemDelegate(parent)
{
}

void CheckBoxItemDelegate::setHandleFilter(HandleFilter handle) noexcept
{
    _handleFilter.swap(handle);
}

void CheckBoxItemDelegate::paint(QPainter *painter,
           const QStyleOptionViewItem &option, const QModelIndex &index) const
{
    if (_handleFilter) {
        if (_handleFilter(index)) {
            QStyledItemDelegate::paint(painter, option, index);
            return;
        }
    }

    QStyleOptionButton opt;
    opt.state |= index.data(Qt::EditRole).toBool() ? QStyle::State_On : QStyle::State_Off;
    opt.state |= QStyle::State_Enabled;

    opt.rect = option.rect;
    QRect checkBoxRect = qApp->style()->subElementRect(QStyle::SE_CheckBoxIndicator, &opt);
    opt.rect.setLeft(option.rect.left() + (option.rect.width() - checkBoxRect.width()) / 2);
    opt.rect.setTop(option.rect.top() + (option.rect.height() - checkBoxRect.height()) / 2);

    qApp->style()->drawControl(QStyle::CE_CheckBox, &opt, painter, option.widget);
}

bool CheckBoxItemDelegate::editorEvent(QEvent *event, QAbstractItemModel *model,
                     const QStyleOptionViewItem &option, const QModelIndex &index)
{
    if (_handleFilter) {
        if (_handleFilter(index)) {
            return QStyledItemDelegate::editorEvent(event, model, option, index);
        }
    }

    if (event->type() == QEvent::MouseButtonDblClick)
        return true;

    if (event->type() == QEvent::MouseButtonRelease)
        return false;

    bool checked = index.data(Qt::EditRole).toBool();
    model->setData(index, !checked, Qt::EditRole);

    emit checkBoxState(!checked);

    return QStyledItemDelegate::editorEvent(event, model, option, index);
}

```

在绘制和编辑事件时就处理了相关操作，这样就能达到点击代理按钮时触发点击事件了。

PS：对于QTableWidget则可以直接设置setCellWidget()小部件到指定的格子上；QListWidget和QTreeWidget则是调用的setItemWidget()函数。



## 2. 完整树模型：Editable TreeModel

树模型里最关键的手法：**QModelIndex 与 TreeItem 之间靠 internalPointer 互相勾连**——`index()` 创建索引时把 `TreeItem*` 藏进去，`getItem()` 再取出来：

```
        TreeItem 树（真实数据层）
        ┌──────────┐
        │ rootItem │
        └────┬─────┘
          ┌──┴───┐
          ▼      ▼
      ┌───────┐ ┌───────┐
      │Item A │ │Item B │
      └───▲───┘ └───────┘
          │ createIndex(row, column, TreeItem*)
          │ 把 TreeItem* 藏进 QModelIndex
    ┌─────┴──────────────┐
    │     QModelIndex    │
    │  row / column /    │
    │  internalPointer ──┼──▶ getItem() 时取出 TreeItem*
    └────────────────────┘
      ★ 无效索引 QModelIndex() 代表"根"
```

以下为 Qt 官方 Editable Tree Model 示例的完整实现（含编者注释）。

```cpp
class TreeItem
{
public:
    explicit TreeItem(const QList<QVariant> &data, TreeItem *parent = nullptr);
    ~TreeItem();
	// 获取指定位置的子项节点
    TreeItem *child(int number);
    // 获取子节点数量
    int childCount() const;
	// 获取列的数量
    int columnCount() const;
    // 返回当前项的指定列的值，注意这个可不是model的那个data()
    QVariant data(int column) const;
    // 指定位置，插入count子项，每个子项都有columns列（扩展子项）
    bool insertChildren(int position, int count, int columns);
    // 指定位置，插入指定数量的列（扩展数据列）
    bool insertColumns(int position, int columns);
    // 返回父项
    TreeItem *parent();
    // 移除指定位置的，count子项行
    bool removeChildren(int position, int count);
    // 移除指定位置的，columns列项
    bool removeColumns(int position, int columns);
	// 返回处于父项所在的位置
    int childNumber() const;
    // 设置指定列的数据
    bool setData(int column, const QVariant &value);
private:
    QList<TreeItem *> childItems;			// 这里是一个列表存储着子项列表
    QList<QVariant> itemData;				// 对应不同角色的存储不同角色的值列表
    TreeItem *parentItem;					// 父项
```

```cpp
bool TreeItem::insertChildren(int position, int count, int columns)
{
    if (position < 0 || position > childItems.size())
        return false;
	// 添加子项
    for (int row = 0; row < count; ++row) {
    	// 创建columns的数据列
        QList<QVariant> data(columns);
        // 创建一个子项
        TreeItem *item = new TreeItem(data, this);
        // 添加子项到指定位置
        childItems.insert(position, item);
    }
    return true;
}

//! [8]
bool TreeItem::insertColumns(int position, int columns)
{
    if (position < 0 || position > itemData.size())
        return false;
	// 当前项扩展列
    for (int column = 0; column < columns; ++column)
        itemData.insert(position, QVariant());
	// 子项扩展列
    for (TreeItem *child : qAsConst(childItems))
        child->insertColumns(position, columns);
    return true;
}

    return parentItem;
}

bool TreeItem::removeChildren(int position, int count)
{
    if (position < 0 || position + count > childItems.size())
        return false;
	// 移除指定数量的子项
    for (int row = 0; row < count; ++row)
        delete childItems.takeAt(position);

    return true;
}
//! [10]

bool TreeItem::removeColumns(int position, int columns)
{
    if (position < 0 || position + columns > itemData.size())
        return false;
	// 移除当前项的指定数据列
    for (int column = 0; column < columns; ++column)
        itemData.remove(position);
	// 子项移除指定的数据列
    for (TreeItem *child : qAsConst(childItems))
        child->removeColumns(position, columns);

    return true;
}

{
    if (column < 0 || column >= itemData.size())
        return false;
	// 设置指定列数据
    itemData[column] = value;
    return true;
}
```

```cpp
#include "treemodel.h"
#include "treeitem.h"

#include <QtWidgets>

//! [0]
TreeModel::TreeModel(const QStringList &headers, const QString &data, QObject *parent)
    : QAbstractItemModel(parent)
{
	// 设置列头标题
    QList<QVariant> rootData;
    for (const QString &header : headers)
        rootData << header;
	// 创建根节点
    rootItem = new TreeItem(rootData);

	// 解析data数据，进行配置初始化
    setupModelData(data.split('\n'), rootItem);
}
//! [0]

//! [1]
TreeModel::~TreeModel()
{
	// 删除根节点
    delete rootItem;
}
//! [1]

//! [2]
int TreeModel::columnCount(const QModelIndex &parent) const
{
    Q_UNUSED(parent);
    return rootItem->columnCount();
}
//! [2]

QVariant TreeModel::data(const QModelIndex &index, int role) const
{
	// 索引无效，则返回无效的值
    if (!index.isValid())
        return QVariant();
	
	// 如果数据角色不是指定的显示角色也不是可编辑的角色，就返回无效的值。角色判断是根据自己的场景来设置的，在自定义model时要结合自身的实际情况
    if (role != Qt::DisplayRole && role != Qt::EditRole)
        return QVariant();
	// 通过索引获取到原本的节点
    TreeItem *item = getItem(index);
	// 节点返回数据
    return item->data(index.column());
}

//! [3]
Qt::ItemFlags TreeModel::flags(const QModelIndex &index) const
{
	// 索引是无效的，则返回项的数据是不可用
    if (!index.isValid())
        return Qt::NoItemFlags;
	// 索引返回可编辑属性 加上一些默认属性，这里可以由视图判断绘制是否选中提供代理编辑
    return Qt::ItemIsEditable | QAbstractItemModel::flags(index);
}
//! [3]

//! [4]
TreeItem *TreeModel::getItem(const QModelIndex &index) const
{
	// 索引有效，那就获取到索创建createIndex()索引时所传递的进来的void* 指针参数
    if (index.isValid()) {
        TreeItem *item = static_cast<TreeItem*>(index.internalPointer());
        if (item)
            return item;
    }
    return rootItem;
}
//! [4]

QVariant TreeModel::headerData(int section, Qt::Orientation orientation,
                               int role) const
{
	// 如果是水平，并且角色为显示时，那就返回根节点所保存的列表头数据
    if (orientation == Qt::Horizontal && role == Qt::DisplayRole)
        return rootItem->data(section);

    return QVariant();
}

//! [5]
QModelIndex TreeModel::index(int row, int column, const QModelIndex &parent) const
{
	// 这里判断父索引时候的，要考虑到下面代码中的createIndex(parentItem->childNumber(), 0, parentItem)，列参数传递是0，否则你会无法理解
    if (parent.isValid() && parent.column() != 0)
        return QModelIndex();
//! [5]

//! [6]
	// 通过索引获取员的项
    TreeItem *parentItem = getItem(parent);
    if (!parentItem)
        return QModelIndex();
	
	// 获取指定行的项，之后创建索引返回
    TreeItem *childItem = parentItem->child(row);
    if (childItem)
        return createIndex(row, column, childItem);
    return QModelIndex();
}
//! [6]

bool TreeModel::insertColumns(int position, int columns, const QModelIndex &parent)
{
	// 插入指定的列数，这里最后必须-1，它是前开后闭假设，position=0;columns=1,那么范围是[0,0] = 所以 [0, 0 + 1 - 1]
	// beginInsertColumns()必须调用，这是局部刷新
    beginInsertColumns(parent, position, position + columns - 1);
    const bool success = rootItem->insertColumns(position, columns);
    endInsertColumns();

    return success;
}

bool TreeModel::insertRows(int position, int rows, const QModelIndex &parent)
{
    TreeItem *parentItem = getItem(parent);
    if (!parentItem)
        return false;        
	// 这里和上面一样，只是改为了行
    beginInsertRows(parent, position, position + rows - 1);
    const bool success = parentItem->insertChildren(position,
                                                    rows,
                                                    rootItem->columnCount());
    endInsertRows();

    return success;
}

//! [7]
QModelIndex TreeModel::parent(const QModelIndex &index) const
{
	// 索引无效
    if (!index.isValid())
        return QModelIndex();
	
	// 这里是获取父项
    TreeItem *childItem = getItem(index);
    TreeItem *parentItem = childItem ? childItem->parent() : nullptr;
	
	// 如果父项等于根项，或者父项为null，那么都返回无效的项，无效的项在这里代表最顶层的项
    if (parentItem == rootItem || !parentItem)
        return QModelIndex();
	// 创建父项索引返回
    return createIndex(parentItem->childNumber(), 0, parentItem);
}
//! [7]

bool TreeModel::removeColumns(int position, int columns, const QModelIndex &parent)
{
	// beginRemoveColumns()参考前面的注释来理解，这里是局部刷新移除的列
    beginRemoveColumns(parent, position, position + columns - 1);
    const bool success = rootItem->removeColumns(position, columns);
    endRemoveColumns();
	
	// 如果列数为0，那么就删除全部节点
    if (rootItem->columnCount() == 0)
        removeRows(0, rowCount());

    return success;
}

bool TreeModel::removeRows(int position, int rows, const QModelIndex &parent)
{
    TreeItem *parentItem = getItem(parent);
    if (!parentItem)
        return false;
	// beginRemoveRows()参考前面的注释来理解，这里是局部刷新移除的行
    beginRemoveRows(parent, position, position + rows - 1);
    const bool success = parentItem->removeChildren(position, rows);
    endRemoveRows();

    return success;
}

//! [8]
int TreeModel::rowCount(const QModelIndex &parent) const
{
	// 父项有效，并且父项的列数大于0，那么返回0行。因为这个父项有问题，因为获取父项的函数，返回的索引列数都为0
    if (parent.isValid() && parent.column() > 0)
        return 0;
	
    const TreeItem *parentItem = getItem(parent);
	// 返回子项数
    return parentItem ? parentItem->childCount() : 0;
}
//! [8]

bool TreeModel::setData(const QModelIndex &index, const QVariant &value, int role)
{
	// 设置数据时，角色要为可编辑角色
    if (role != Qt::EditRole)
        return false;

    TreeItem *item = getItem(index);
    // 设置数据
    bool result = item->setData(index.column(), value);
	
	// 设置数据完成后要发出数据改变的信号来刷新视图
    if (result)
        emit dataChanged(index, index, {Qt::DisplayRole, Qt::EditRole});

    return result;
}

bool TreeModel::setHeaderData(int section, Qt::Orientation orientation,
                              const QVariant &value, int role)
{
    if (role != Qt::EditRole || orientation != Qt::Horizontal)
        return false;

    const bool result = rootItem->setData(section, value);
	
	// 列头数据被修改，发出信号通知视图
    if (result)
        emit headerDataChanged(orientation, section, section);

    return result;
}

void TreeModel::setupModelData(const QStringList &lines, TreeItem *parent)
{
	// 这个函数不用在意，这是示例初始化模型数据，此时模型还未设置到视图中，所以不用发出视图刷新相关的指示信号操作
    QList<TreeItem *> parents;
    QList<int> indentations;
    parents << parent;
    indentations << 0;

    int number = 0;

    while (number < lines.count()) {
        int position = 0;
        while (position < lines[number].length()) {
            if (lines[number].at(position) != ' ')
                break;
            ++position;
        }

        const QString lineData = lines[number].mid(position).trimmed();

        if (!lineData.isEmpty()) {
            // Read the column data from the rest of the line.
            const QStringList columnStrings =
                lineData.split(QLatin1Char('\t'), Qt::SkipEmptyParts);
            QList<QVariant> columnData;
            columnData.reserve(columnStrings.size());
            for (const QString &columnString : columnStrings)
                columnData << columnString;

            if (position > indentations.last()) {
                // The last child of the current parent is now the new parent
                // unless the current parent has no children.

                if (parents.last()->childCount() > 0) {
                    parents << parents.last()->child(parents.last()->childCount()-1);
                    indentations << position;
                }
            } else {
                while (position < indentations.last() && parents.count() > 0) {
                    parents.pop_back();
                    indentations.pop_back();
                }
            }

            // Append a new item to the current parent's list of children.
            TreeItem *parent = parents.last();
            parent->insertChildren(parent->childCount(), 1, rootItem->columnCount());
            for (int column = 0; column < columnData.size(); ++column)
                parent->child(parent->childCount() - 1)->setData(column, columnData[column]);
        }
        ++number;
    }
}
```

## 4. 项目案例

### 案例一：NetworkAdapterModel——基础列表模型暴露 QML

需求很简单：设置页里展示本机网卡列表（连接名、描述、IP、网关），网络变化后允许手动刷新。模型直接继承 QAbstractListModel，头文件关键部分如下：

```cpp
class NetworkAdapterModel : public QAbstractListModel
{
    Q_OBJECT
    QML_ELEMENT
    Q_PROPERTY(int count READ rowCount NOTIFY countChanged)

public:
    enum Role {
        NameRole = Qt::UserRole + 1,    ///< 连接名（如"以太网"、"WLAN"）
        DescriptionRole,                ///< 网卡硬件描述
        IpAddressesRole,                ///< IPv4 地址列表（QStringList）
        GatewaysRole,                   ///< IPv4 网关列表（QStringList）
    };
    Q_ENUM(Role)

    explicit NetworkAdapterModel(QObject *parent = nullptr);

    int rowCount(const QModelIndex &parent = {}) const override;
    QVariant data(const QModelIndex &index, int role) const override;
    QHash<int, QByteArray> roleNames() const override;

    /// 重新枚举系统网络适配器（全量重置）
    Q_INVOKABLE void refresh();

signals:
    void countChanged();
    // ...
};
```

对照前面的 PersonModel 最小示例，实战代码多出来的东西恰好都是"惯例级"的：

+ **QML_ELEMENT 免注册**。前文用 `qmlRegisterType<PersonModel>("MyApp.Models", 1, 0, "PersonModel")` 手动注册；实战里类上一个 `QML_ELEMENT` 宏，配合 CMake 的 `qt_add_qml_module` 就自动完成注册，QML 里 import 模块后直接用，少一道 main.cpp 的手续。
+ **Role 枚举从 Qt::UserRole + 1 起编号**，并用 Q_ENUM 注册进元对象系统——这样 QML 里也能引用枚举值（如 `NetworkAdapterModel.NameRole`），调试和写 QML 工具代码时不靠魔法数字。
+ **Q_PROPERTY(int count READ rowCount NOTIFY countChanged)**：把行数做成 QML 可绑定的属性。QML 里 `model.count` 直接绑定空态提示（"暂无网卡"）之类的 UI，行数变化自动刷新。
+ **Q_INVOKABLE refresh()**：QML 主动触发刷新的入口。实现内部是 `beginResetModel()` → 清空重新枚举 → `endResetModel()` → `emit countChanged()`，正是前文"begin/end 成对包裹"的铁律应用——全量重建走 reset 而不是逐行增删，简单且语义正确。

data() / roleNames() 的实现则与 PersonModel 如出一辙：switch 按 role 分发，roleNames() 返回 `{NameRole, "name"}` 这样的映射表。这也说明：**最小示例与实战的距离，只是枚举、属性、刷新入口这些"外壳"，内核完全一样。**

### 案例二：SeatGridProxyModel——QSortFilterProxyModel 做分页

需求进阶了：教室席位网格，源模型是"已配对设备"列表（几十上百台），GridView 每页只显示 3x3 或 4x4 一页，要翻页、要切布局。思路是**不动源模型，在它和视图之间夹一层代理**：

```
 源模型（已配对设备）─▶ SeatGridProxyModel（分页窗口）─▶ QML GridView
        ▲                        │                          delegate
        │ 字段变化按行转发        │ 翻页/布局切换 → 整体 reset
        └────────────────────────┘
```

分页的核心实现出人意料地简单——重写 filterAcceptsRow()，只放行当前页窗口内的源行：

```cpp
bool SeatGridProxyModel::filterAcceptsRow(int sourceRow, const QModelIndex &sourceParent) const
{
    Q_UNUSED(sourceParent);
    // 只放行当前页窗口内的行
    const int start = m_currentPage * m_pageSize;
    return m_pageSize > 0 && sourceRow >= start && sourceRow < start + m_pageSize;
}
```

QSortFilterProxyModel 内部自动完成源索引到代理索引的映射，视图看到的 rowCount() 就是当前页的行数。翻页时改 `m_currentPage` 再走 begin/endResetModel，QSFPM 的映射按新窗口懒重建即可（Qt 文档认可这种用法）。

这个模型里值得学的还有三个设计点：

**1. 追加角色的角色号要远离源模型区段。** 代理在源模型角色之外加了一个"整行快照"角色，编号刻意跳到 `Qt::UserRole + 100`：

```cpp
/// 源模型角色之外追加的角色（角色号远离源模型区段，防冲突）
enum ExtraRole {
    ItemDataRole = Qt::UserRole + 100  ///< 整行 QVariantMap 快照
};
Q_ENUM(ExtraRole)
```

因为 QSFPM 会把源模型的角色原样透传，如果追加角色的编号落在源模型的区段里就会撞号，data() 里根本分不清是谁的角色。留足间隔是最省心的防冲突手段。

**2. ItemDataRole 快照：一次取整行。** delegate 往往要用到一行的多个字段，逐个 role 调 data() 就是多次虚函数调用；快照角色遍历源模型的 roleNames() 一次性组装成 QVariantMap 返回，QML 里 `itemData.name`、`itemData.status` 随便取，而且与源模型的具体角色集解耦——源加了新角色，代理一行代码都不用改：

```cpp
QVariant SeatGridProxyModel::data(const QModelIndex &index, int role) const
{
    if (role == ItemDataRole) {
        const QModelIndex srcIndex = mapToSource(index);
        if (!srcIndex.isValid() || !sourceModel())
            return {};
        // 整行快照：遍历源 roleNames 组装，与源模型具体角色集解耦
        QVariantMap map;
        const QHash<int, QByteArray> names = sourceModel()->roleNames();
        for (auto it = names.constBegin(); it != names.constEnd(); ++it)
            map[QString::fromUtf8(it.value())] = sourceModel()->data(srcIndex, it.key());
        return map;
    }

    return QSortFilterProxyModel::data(index, role);
}
```

但有一个坑：QSFPM 转发源的 dataChanged 时**只按源角色转发**，ItemDataRole 这个自造角色永远收不到刷新通知。所以要自己接源的 dataChanged，算出与当前页窗口的行交集，补发一次带 ItemDataRole 的 dataChanged：

```cpp
void SeatGridProxyModel::onSourceDataChanged(const QModelIndex &topLeft, const QModelIndex &bottomRight,
                                             const QList<int> &roles)
{
    Q_UNUSED(roles);
    // QSFPM 只按源角色转发 dataChanged，itemData 快照角色需按窗口交集补发
    const int start = m_currentPage * m_pageSize;
    const int lo = qMax(0, topLeft.row() - start);
    const int hi = qMin(rowCount() - 1, bottomRight.row() - start);
    if (lo > hi)
        return;
    emit dataChanged(index(lo, 0), index(hi, 0), {ItemDataRole});
}
```

**3. 信号语义分层：重建与不重建的取舍。** 这是整个案例最精髓的一点。该类的头文件注释里明确约定了信号语义：

+ **翻页 / 布局切换** → beginResetModel/endResetModel **整体重建**，delegate 全部销毁重建（视图经 modelAboutToBeReset/modelReset 先行停流）；
+ **源字段变化**（设备上下线、状态变化）→ QSFPM 按行转发 dataChanged，**delegate 不重建**，就地刷新；
+ **源结构变化**（设备增删）→ QSFPM 内部按行增删/重排转发，代理只管页码钳制和 pageCount 通知。

为什么要这么较真地区分？因为**席位 delegate 里嵌着 mpv 视频播放器**，播放器随 delegate 存亡——delegate 一重建，视频流就要断流重连，几十路同时重建就会卡死。所以"字段更新"这条高频路径绝不允许触发 reset，只能用按行的 dataChanged；而翻页这种本来就要换一批画面的操作，才用 reset 整体重建。发什么信号，本质是在向视图承诺"变动的范围有多大"，这个承诺必须与业务代价匹配。

```
 信号语义分层（承诺的变动范围 ↔ 业务代价）
 ├─ dataChanged（按行）  delegate 就地刷新，播放器不动 ✔ 高频路径
 ├─ rowsInserted/Removed 按行增删，只影响对应 delegate
 └─ modelReset（整体）    delegate 全部重建，视频断流重连
        ★ 只在翻页/布局切换时用，字段更新严禁走这里
```

另外两个小细节：count 属性的通知接线里专门 connect 了 `layoutChanged`——因为数据变化触发 QSFPM 重过滤/重排序使行进出时，Qt 发的是 layoutChanged 而非 rowsInserted/Removed，缺了它 QML 永远收不到 count 更新；页码在 setCurrentPage/setPageSize/源结构变化三处都做钳制（clamp 到 `[0, pageCount-1]`），保证任何路径下页码不越界。

### 实战原则小结

从这两个案例可以提炼出几条实战原则：

1. **模型链组合优于单模型塞所有逻辑。** 分页、过滤、排序都是"叠加层"职责，交给 QSortFilterProxyModel 之类的代理模型夹在中间，源模型保持纯粹——要换分页策略只换代理，不动数据层。
2. **信号语义要分层设计。** reset（重建）、按行增删、按行 dataChanged 是三种不同粒度的承诺，选哪一档要看 delegate 重建的业务代价；高频更新路径必须用最小粒度的信号。
3. **角色号要有规划。** 自定义角色从 UserRole+1 起；代理模型追加角色时跳号远离源区段（如 +100），并用 Q_ENUM 注册让 QML 可引用，杜绝魔法数字。
4. **QML_ELEMENT 一体化暴露。** 配合 Q_PROPERTY（count 等）与 Q_INVOKABLE（refresh 等），模型从注册、行数绑定到主动刷新全部自给自足，QML 侧零胶水代码。
