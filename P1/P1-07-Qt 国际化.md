# P1-07 Qt 国际化

> 本文基于 **Qt 6.8.3**。国际化（i18n）的核心矛盾是：代码里的字符串是写死的，
> 界面上的语言却要能切换。Qt 的答案是"标记 → 提取 → 翻译 → 加载"四步工具链。
> lupdate / linguist 的完整选项手册见 P2-04。

## 1. 整体流程

Qt 国际化的全流程，四个工具各司其职：

```
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ tr()    │    │ lupdate  │    │ linguist │    │ lrelease │
│ 包裹文本 ├──▶│ 提取文本 ├──▶│ 人工翻译 ├──▶│ 编译发布 ├──▶┐
└─────────┘    └──────────┘    │ (.ts 文件)│    │ (.qm 文件)││
                               └──────────┘    └──────────┘│
                                                           ▼
                                              ┌──────────────────┐
                                              │ QTranslator 加载  │
                                              │ .qm → 界面换语言  │
                                              └──────────────────┘
```

- **tr()**：在源码里标记"这个字符串需要翻译"；
- **lupdate**：扫描源码，把标记的字符串提取成 `.ts` 文件（XML 格式）；
- **linguist**：可视化翻译工具，译者在 `.ts` 上工作（不必碰代码）；
- **lrelease**：把 `.ts` 编译成紧凑的 `.qm` 二进制，供程序加载。

三个工具都在 Qt 套件的 `bin` 目录下。手动命令行用法：

```shell
# 提取：扫描目录生成 .ts
lupdate ./src -ts app_zh_CN.ts

# 发布：.ts 编译为 .qm
lrelease app_zh_CN.ts
```

## 2. 提取与发布的工程化：推荐脚本而非 IDE 集成

Qt 6.2 起官方提供了 `qt_add_translations` 把 lupdate/lrelease 挂进 CMake，Qt Creator 也有相应的翻译支持。但**就 6.8.3 的现状来说，这套集成还不够完善和成熟**（目标语言管理、增量更新、多模块拆分的体验都有欠缺）。实际项目里更可控的做法是：**手动执行 lupdate 命令提取，并写成脚本反复使用**——这也是多数成熟 Qt 项目的现状。

一个 Windows 批处理脚本示例（`update_ts.bat`）：扫描多个模块目录，生成一个 .ts：

```bat
lupdate D:\project\MainApp ^
D:\project\Components\LiquidPump ^
D:\project\Components\ScriptWidget ^
-ts app_zh_CN.ts
```

`^` 是批处理的续行符。源码变动后重跑一遍脚本即可增量更新 .ts（已有翻译保留、新串追加、消失的串标记 obsolete 待清理）。这样的好处：

- **可控**：扫哪些目录、生成哪几个 .ts，一目了然，不受 IDE 配置变迁影响；
- **可重复**：脚本进版本库，团队任何成员、CI 都能跑出同样结果；
- **可拆分**：想按模块拆 .ts，就写多条 lupdate 命令，各管各的（§4.1 会讲为什么推荐拆分）。

★ 另一个必须知道的限制：**lupdate 靠文本匹配识别翻译标记，不理解宏**。所以想被提取，代码里必须显式出现 `tr("...")` / `QT_TR_NOOP("...")` 这些字面写法——自己封装的宏包裹一层它就认不出了。确需自定义函数名时，用 `-tr-function-alias` 选项告诉 lupdate（详见 P2-04）。

## 3. tr() 家族

### 3.1 tr() 与上下文

`tr()` 不是全局函数，它是 QObject 的成员。你在某个 QObject 派生类的成员函数里写 `tr("...")`，本质等价于：

```cpp
QCoreApplication::translate("你的类名", "...");
```

**tr() 自动拿当前类名作为上下文（ctx）**。所以翻译表里每条翻译由"**上下文 + 源字符串**"二元组定位：

```
 代码： class WorkWidget { ... tr("Switch Languages") ... }
                          │
                          ▼ tr() 自动带上类名
 .ts 条目： <context><name>WorkWidget</name> …
           <message><source>Switch Languages</source>
                    <translation>切换语言</translation>
```

这一点在 Qt Linguist 里是直观可见的：**每个类名在 linguist 里显示为一个独立的类别分组**，译者按类逐组翻译——所以类名选得有意义，翻译效率也会更高。

同一句话在不同类里可以译得不同（比如 "Open" 在菜单类里是"打开"，在按钮类上是"开"），靠的就是上下文隔离。同上下文内还需区分时，用 `tr()` 的第二个参数（disambiguation 注释）。

由此也推出一个实用结论：**想让某个字符串拥有自定义的上下文，就用 `QCoreApplication::translate("自定义名", ...)` 或 QT_TR_NOOP 文本表模式（§3.3）**，而不是依赖它碰巧写在哪个类里。

### 3.2 占位符与复数

```cpp
// 占位符：%1 %2，翻译时语序可调
statusBar()->showMessage(tr("%1 of %2 files copied").arg(done).arg(total));

// 复数：%n 按数量自动选单复数形式（不同语言复数规则不同）
tr("%n file(s) deleted", nullptr, count);
```

### 3.3 QT_TR_NOOP：延迟翻译

有些字符串**定义的时候还不需要翻译**（静态文本表、配置项、菜单模板），用到的那一刻才需要当前语言的译文——这就是 `QT_TR_NOOP` 的场景。它本身什么都不做，只是给 lupdate 的提取标记：

```cpp
// 文本表类：类名就是 translate() 的上下文前缀
class JieTranslate : public QObject
{
    Q_OBJECT
public:
    constexpr static const char *Translates[] =
    {
        QT_TR_NOOP("国际化翻译"),
        QT_TR_NOOP("光耦检测"),
        QT_TR_NOOP("堆栈测试")
    };
};
```

取用时用 `QCoreApplication::translate(ctx, str)`——ctx 是类名，str 是表中的源串：

```
 QT_TR_NOOP 定义时：  类名 JieTranslate  +  字符串 "光耦检测"
                         │                       │
                         ▼                       ▼
 translate() 取用时： translate("JieTranslate", "光耦检测")
                         │                       │
                       ctx 前缀                str 后缀
```

这个机制的好处：翻译文本集中定义、可复用、lupdate 照常提取。Qt Designer 生成的 `retranslateUi()` 里用的正是 `QCoreApplication::translate("ClassName", ...)` 这套——同一个机制。家族里还有 `QT_TRANSLATE_NOOP`（显式指定上下文）、`QT_TR_N_NOOP`（复数版）等，用法同理。

## 4. 加载与运行时切换

### 4.1 加载 .qm

```cpp
QTranslator *translator = new QTranslator;
if (translator->load("app_zh_CN.qm", qmDir))
    QCoreApplication::installTranslator(translator);
else
    delete translator;
```

★ `QTranslator` 安装后必须**常驻内存**（所以 new 且不 delete，加载失败才释放）。翻译文件可以装多个——**建议按模块拆分多个 .ts/.qm**，修改时粒度小，也好多人协作。一个批量加载目录下全部 .qm 的实用帮助类：

```cpp
class TranslateHelper
{
public:
    static void loadAll(const QDir &dir)
    {
        const QFileInfoList files = dir.entryInfoList();
        for (const QFileInfo &file : files) {
            if (file.suffix() != QLatin1String("qm"))
                continue;
            auto *translator = new QTranslator;
            if (translator->load(file.absoluteFilePath()))
                QCoreApplication::installTranslator(translator);
            else
                delete translator;
        }
    }
};
```

### 4.2 运行时切换语言

切换语言 = 卸载旧 translator + 装新 translator，然后**重新给控件设置文本**——已经设好的文本不会自动变：

```
 切换语言的动作序列
  removeTranslator(旧) → installTranslator(新)
        → 触发 LanguageChange 事件
        → 各界面重新 tr()/retranslateUi() 刷文本 ★
```

- Qt Designer 生成的界面：再调一次 `retranslateUi()` 即可（它会重新走一遍 translate()）；
- 手写界面：在 `changeEvent()` 里响应 `QEvent::LanguageChange`，重设所有文本；
- QML 侧用 `qsTr()` / `qsTrId()` 标记，同样被 lupdate 识别，切换机制不同（重载引擎或绑定刷新），QML 线再展开。

## 5. 常见坑

```
 国际化常见坑
 ├─ tr() 在静态初始化期调用：translator 还没装，
 │   拿到的是原文——延迟到运行时再取（QT_TR_NOOP 模式）
 ├─ 字符串拼接破坏翻译：tr("删除") + name + tr("文件")
 │   每种语言语序不同，拼出来是错的——用 %1 占位符整句翻译
 ├─ 宏封装 tr()：lupdate 文本匹配识别不了（§2 的铁律）
 └─ 编码：Qt 6 源文件默认按 UTF-8 处理，保证源文件
     存为 UTF-8（VS 里注意加 /utf-8 或存 BOM）
```

## 6. 小结

```
 本文要点回顾
  ├─ 四步工具链：tr() 标记 → lupdate 提取 → linguist 翻译
  │              → lrelease 发布
  ├─ 提取/发布推荐脚本化手动执行（lupdate 批处理），
  │   IDE/CMake 集成尚不成熟
  ├─ 定位 = 上下文（tr() 自动取类名）+ 源串；%1 占位、%n 复数
  ├─ QT_TR_NOOP：定义时标记、取用时翻译
  ├─ 切换语言后必须重新设置文本（retranslateUi /
  │   LanguageChange）
  └─ lupdate 靠文本匹配：翻译标记必须字面出现
```
