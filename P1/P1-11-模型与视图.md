# P1-11 模型与视图

> 本文基于 **Qt 6.8.3**。模型/视图是 Qt 数据展示体系的总框架，Widgets 和 QML
> 共用同一套模型抽象。本篇讲架构思想与标准用法；TreeModel、自定义委托、
> 层级表头、分页代理等完整实现见 P3-03。

## 1. 为什么 Qt 要发明"模型/视图"

入门时都用过 `QTableWidget`：`setItem(row, col, item)` 直接把数据塞进控件。简单直接，但数据一多、需求一复杂就露馅：

```
 直接操作控件（QTableWidget）        模型/视图（QTableView + Model）
 ┌──────────────┐                  ┌──────┐   ┌──────┐
 │ 数据住在控件里 │                  │ 数据  │──▶│ 模型  │
 │ 想换个视图？   │                  └──────┘   └──┬───┘
 │ 只能搬数据重来 │                        ┌───────┼───────┐
 └──────────────┘                        ▼       ▼       ▼
                                      表格视图 列表视图 树视图
                                      （同一份数据，多种展示）★
```

问题本质：**数据和显示焊死在了一起**。模型/视图架构把两者拆开——数据住在模型里，视图只管显示，同一份数据可以同时喂给表格、列表、树三种视图，数据一变全部自动刷新。

Qt 采用 **Model / View / Delegate** 三分结构（与传统 MVC 不完全等同：Qt 把 View 和 Controller 合并进了视图，另设 Delegate 负责绘制与编辑）：

```
 ┌──────────────┐   dataChanged 信号   ┌──────────────┐
 │     Model    │─────────────────────▶│     View     │
 │ （数据接口）  │                      │   （显示）    │
 │              │◀────── QModelIndex ──│              │
 └──────▲───────┘   按 role 取数据      └──────▲───────┘
        │                                      │
        │ setData 写回                        │ 用户操作（双击）
 ┌──────┴───────┐                              │
 │   Delegate   │◀─────────────────────────────┘
 │ （绘制/编辑） │
 └──────────────┘
```

## 2. 两个核心概念

### 2.1 QModelIndex：数据的临时句柄

视图向模型要数据，靠的不是指针也不是行号，而是 `QModelIndex`——一个记录"第几行、第几列、属于哪个模型、父索引是谁"的**定位句柄**。数据的读写永远要回到模型：`model->data(index, role)`。

```
        一个单元格 = 一个 QModelIndex
        ├─ row / column     行列位置
        ├─ parent           父索引（树模型用；list/table 恒为无效索引）
        └─ internalPointer  内部指针（自定义树模型藏数据节点用）

        ★ 无效索引 QModelIndex() 代表"根"
```

两个使用纪律：

- **不要长期持有 QModelIndex**——数据增删后它就失效了；需要长期引用用 `QPersistentModelIndex`；
- 数据真正的读写永远通过 `model->data()` / `model->setData()` 回到模型。

### 2.2 role：数据的维度

同一个单元格不只有"显示的文本"，还可以同时携带图标、勾选状态、字体、背景色……视图取数据时要说明"我要哪个维度"，这个维度就是 role：

```
        一个单元格 = 一个 QModelIndex
        ┌──────────────────────────────┐
        │ DisplayRole     显示文本      │
        │ DecorationRole  图标/装饰     │
        │ EditRole        编辑用的数据  │
        │ CheckStateRole  勾选状态      │
        │ FontRole        字体          │
        │ BackgroundRole  背景色        │
        │ UserRole + N    自定义数据 ★  │
        └──────────────────────────────┘
```

常用预定义角色（`Qt::ItemDataRole`）：`DisplayRole`（文本）、`DecorationRole`（图标）、`EditRole`（编辑值）、`CheckStateRole`（勾选）、`ToolTipRole`、`FontRole`、`BackgroundRole`、`TextAlignmentRole`、`SizeHintRole`。

★ **自定义业务数据一律从 `Qt::UserRole`（0x0100）起步编号**（UserRole、UserRole+1……），与预定义角色错开。QML 侧会看到：模型暴露给 QML 的角色名就是从 UserRole+1 开始命名的。

## 3. Widgets 侧的标准用法

### 3.1 开箱即用的模型

大多数时候不需要自己写模型：

```
 现成模型选型
 ├─ QStringListModel     字符串列表（ QListView 绝配）
 ├─ QStandardItemModel   通用表格/树，项即数据（最常用）
 ├─ QSqlTableModel /
 │   QSqlQueryModel      数据库表直挂视图（见 P1-08）
 └─ QSortFilterProxyModel 排序/过滤代理（见 §4）
```

`QStandardItemModel` 的典型用法三行成型：

```cpp
auto *model = new QStandardItemModel(this);
model->setHorizontalHeaderLabels({QStringLiteral("姓名"), QStringLiteral("座位")});
model->appendRow({new QStandardItem(QStringLiteral("张三")),
                  new QStandardItem(QStringLiteral("A-03"))});
ui->tableView->setModel(model);
```

### 3.2 什么时候需要自定义模型

`QStandardItemModel` 把每个单元格存成一个 `QStandardItem` 对象——方便但重。数据量大（几万行以上）、或数据本来就在自己的结构里（数据库、设备列表）时，就该自定义模型：让 `data()` 直接从你的数据结构里取，零拷贝。

继承选型：列表用 `QAbstractListModel`，表格用 `QAbstractTableModel`，树才用 `QAbstractItemModel` 全量实现。五个核心接口的分工：

```
 QAbstractItemModel 核心接口
 ├─ rowCount()     行数（视图要画多少行）
 ├─ columnCount()  列数
 ├─ index()        由"行、列、父索引"创建 QModelIndex
 ├─ parent()       由索引反查父索引（list/table 恒无效，
 │                 只有树模型才真正用到）
 └─ data()         由"索引 + role"取数据
        ★ 继承 List/TableModel 时 index()/parent() 基类已实现，
          只需补 rowCount()/columnCount()/data()
```

一个最小可用的自定义表格模型骨架：

```cpp
class DeviceModel : public QAbstractTableModel
{
    Q_OBJECT
public:
    int rowCount(const QModelIndex & = {}) const override { return m_devices.size(); }
    int columnCount(const QModelIndex & = {}) const override { return 2; }

    QVariant data(const QModelIndex &index, int role) const override
    {
        if (!index.isValid() || role != Qt::DisplayRole)
            return {};
        const Device &d = m_devices.at(index.row());
        return index.column() == 0 ? d.name : d.address;
    }
private:
    QList<Device> m_devices;
};
```

### 3.3 数据变更的铁律：begin/end 成对

模型数据变了，视图怎么知道？靠模型的通知。改数据有一条铁律：**begin/end 必须成对调用，真实修改夹在中间**：

```
 beginInsertRows(parent, first, last)   ← 先声明"我要插入了"
      │
      ▼
 真正修改内部数据（insert/append……）
      │
      ▼
 endInsertRows()                      ← 宣告完毕，视图此刻刷新
```

为什么不能先改数据再 begin？因为视图在 begin 时刻就记录受影响范围（把受影响的 QModelIndex 转成持久索引）。先改数据，视图拿到的行数与模型已不一致——轻则刷新错乱，重则越界崩溃。remove/move 系列同理。`dataChanged(index, index, {roles})` 用于内容不变、仅值变化的场景。

### 3.4 委托：单元格的绘制与编辑

视图默认的文本展示不够用时（进度条、复选框、彩色徽章），自定义委托。委托分两件事：**绘制**（`paint()` + `sizeHint()`）和**编辑**（创建编辑器 → 装数据 → 写回模型）。编辑的四个函数有固定调用时序：

```
 用户双击单元格
      │
      ▼
 createEditor()           创建编辑器控件（1）
      ▼
 updateEditorGeometry()   把编辑器摆到单元格位置（2）
      ▼
 setEditorData()          把模型数据装进编辑器（3）
      ▼ 用户编辑完成（回车/失焦），代理 emit commitData
 setModelData()           把编辑器数据写回模型（4）
      ▼
 模型 emit dataChanged ──▶ 视图刷新
```

推荐继承 `QStyledItemDelegate`（默认绘制保留、样式表生效），只覆盖需要的部分。对于"不需要编辑器、直接响应点击"的场景（单元格里的 CheckBox/按钮），走 `paint()` 画形状 + `editorEvent()` 直接改模型——完整实现（含进度条、复选框两个完整委托）见 **P3-03**。

## 4. 代理模型：不改原模型的管道

需求：同一份数据，一个视图要排序、一个视图只显示某类设备。难道复制两份模型？`QSortFilterProxyModel` 给出的思路是**管道**：

```
 ┌────────┐   ┌──────────────────┐   ┌────────┐
 │ 源模型  │──▶│ QSortFilterProxy │──▶│  视图   │
 │（不动） │   │ 排序/过滤/适配    │   │        │
 └────────┘   └──────────────────┘   └────────┘
   代理模型插在中间，源模型零改动；
   索引经 mapToSource / mapFromSource 双向换算 ★
```

```cpp
auto *proxy = new QSortFilterProxyModel(this);
proxy->setSourceModel(model);
proxy->setFilterRegularExpression(QStringLiteral("^A-"));   // 只显示 A 区座位
proxy->setFilterKeyColumn(1);
ui->tableView->setModel(proxy);
```

★ 使用代理模型后最高发的 bug：**视图给的 index 是代理坐标系**，要操作源模型数据必须先 `proxy->mapToSource(index)`，忘了映射就是张冠李戴。继承 `QSortFilterProxyModel` 覆盖 `filterAcceptsRow()` 还能做任意自定义过滤/适配——分页代理的实战案例见 P3-03。

## 5. QML 侧的模型视图

### 5.1 概念对应

QML 没有"委托类"，委托是一个 **QML 组件**；视图也不再分 List/Table/Tree 控件，而是 `ListView` / `GridView` / `TableView`：

```
 Widgets 侧                QML 侧
 ├─ QAbstractItemModel  →  同一个 C++ 模型（roles 暴露）
 ├─ QListView/QTableView →  ListView / GridView / TableView
 └─ QStyledItemDelegate  →  delegate: Item { ... }（QML 组件）
```

```qml
ListView {
    width: 200; height: 300
    model: deviceModel          // C++ 注册的 QAbstractListModel
    delegate: Rectangle {
        width: ListView.view.width; height: 40
        color: index % 2 ? "#f0f0f0" : "white"
        Text { text: name + "  " + address }   // 直接用角色名绑定 ★
    }
}
```

### 5.2 C++ 模型喂给 QML：roleNames

QML 的 delegate 里能直接写 `name`、`address`，是因为模型把这些角色名暴露了出来。`QAbstractListModel` 的角色名来自 `roleNames()`：

```cpp
QHash<int, QByteArray> DeviceModel::roleNames() const
{
    return {
        { Qt::UserRole + 1, "name" },
        { Qt::UserRole + 2, "address" },
    };
}

QVariant DeviceModel::data(const QModelIndex &index, int role) const
{
    if (!index.isValid()) return {};
    const Device &d = m_devices.at(index.row());
    switch (role) {
    case Qt::UserRole + 1: return d.name;
    case Qt::UserRole + 2: return d.address;
    }
    return {};
}
```

角色从 `UserRole + 1` 起编号（呼应 §2.2 的红线），`roleNames()` 建立"角色号 ↔ QML 属性名"的映射，delegate 里按名取用。模型经 `QML_ELEMENT` + 上下文属性/`qmlRegisterType` 暴露给 QML（注册方式见 P1-10）。

### 5.3 两侧的取舍

- Widgets 侧：桌面复杂表格/树成熟稳定，默认外观即原生；
- QML 侧：delegate 是任意 QML 组件，自定义视觉的自由度大得多，动画天然支持；
- 模型层是同一份 C++ 抽象——**一套模型，两侧通用**，这正是架构分离的回报。

## 6. 性能要点

```
 模型视图性能红线
 ├─ 大批量增删：用 begin/end 圈定范围一次通知，
 │   禁止逐行发信号（每行一次全量刷新 = O(n²)）
 ├─ dataChanged 给精确范围 + roles，别广播全表
 ├─ 视口外的项：data() 必须廉价——视图只问可见行，
 │   但会在滚动时高频调用
 ├─ data() 里别做 IO/排序/字符串拼接，数据提前备好
 └─ QTableWidget 的 ResizeToContents 陷阱（见 P1-05）
```

核心心智：视图是"按需拉取"的——它只问可见区域的 `data()`，但滚动时调用频率极高。`data()` 越廉价，滚动越顺滑。

## 7. 小结

```
 本文要点回顾
  ├─ 架构：Model（数据接口）/ View（显示）/ Delegate（绘制编辑）
  ├─ QModelIndex 是临时句柄；role 是数据维度；
  │   自定义角色从 UserRole 起编号
  ├─ Widgets：现成模型够用；自定义继承 List/TableModel；
  │   改数据 begin/end 成对
  ├─ 代理模型管道：排序过滤不动源模型；
  │   注意 mapToSource 坐标换算
  ├─ QML：delegate 是 QML 组件；C++ 模型靠 roleNames 暴露
  └─ 性能：通知给精确范围；data() 必须廉价
```
