# P1-10 Qt6 模块系统

> 本文基于 **Qt 6.8.3**。Qt6 在 QML 工程组织上有一个根本性的转变：
> **以模块为单元组织功能**。本篇讲清这套模块系统，以及配套的 CMake 工程惯例。
> C++ 导出类型依赖的元对象基础见 P1-01。

## 1. Qt6 为什么推动模块化

Qt5 时代的 QML 工程常常是散乱的：qml 文件直接塞进主程序的资源文件，加载靠写死路径，C++ 类型靠手写 `qmlRegisterType`。Qt6 的答案是：**做功能先做成 QML 模块，再把模块引入项目**。

```
Qt5 思路：裸路径加载                  Qt6 思路：模块化加载
┌─────────────────────┐             ┌──────────────────────────┐
│ engine.load("qrc:/  │             │ import DrawPanelQuick    │
│   Main.qml")        │             │ engine.loadFromModule(   │
│ 路径写死，文件跟着主 │    ──▶      │   "DrawPanelQuick",      │
│ 程序走，无法复用     │             │   "Main")                │
└─────────────────────┘             │ 模块自带类型与资源，可复用 │
                                    └──────────────────────────┘
```

一个 QML 模块有自己的 URI（导入路径）、版本号、`qmldir` 定义文件和独立的资源系统。好处实实在在：

- **可复用**：模块可以跨项目引入，而不是复制源码；
- **工具链可见**：`qmllint` 静态检查、`qmlcachegen` 预编译都基于模块定义工作；
- **加载语义清晰**：`loadFromModule()`（Qt 6.5 起）按"模块名 + 类型名"加载，效果等同 QML 里 `import URI` 再创建类型——文件放哪不再是主程序要关心的事。

## 2. qt_add_qml_module 详解

### 2.1 最小示例与核心概念

```cmake
qt_add_qml_module(DrawPanelQuick
    URI DrawPanelQuick
    VERSION 1.0
    QML_FILES DrawPanelControl.qml
    SOURCES MyPainter.h MyPainter.cpp
    RESOURCES icons/pen.png
)
```

先澄清三个概念的关系（最容易混的地方）：

```
 target（CMake 层）     URI（QML 层）        plugin（运行时）
 DrawPanelQuick.dll    import DrawPanelQuick  DrawPanelQuickplugin.dll
 构建出的库本体         导入路径/模块名         未链接时动态加载的入口
 供 target_link_       供 import /            qmldir 里记录它的名字
   libraries() 链接     loadFromModule() 使用
```

- **backing target**：模块的库本体，装 C++ 源码、qml、资源；主程序可以直接 link；
- **plugin target**：一个极简的插件类，负责在主程序**没链接** backing 库时让 QML 引擎动态加载模块。链接了 backing 时插件不会被加载，启动更快；
- 第一个参数是 exe（可执行程序）时不生成插件，模块直接编进程序本体。

★ 一条工程约定：模块的**源码目录结构应与 URI 的 target path 一致**（URI 的点换成 `/`），否则构建会警告。推荐布局：

```
src/
├─ app/                    # 主程序
│   ├─ CMakeLists.txt      # qt_add_executable + 链接模块
│   └─ Main.qml
└─ MyThings/
    └─ Panels/             # URI MyThings.Panels
        ├─ CMakeLists.txt  # qt_add_qml_module(... URI MyThings.Panels)
        ├─ Panel.qml
        └─ panelmodel.h/.cpp
```

target 与 URI 同名不是必需，但强烈建议——import 名、target 名、目录名三者对应，工程可读性天壤之别。

### 2.2 常用参数速查

`qt_add_qml_module()` 的完整签名有三十多个参数，日常只需要这几个：

| 参数 | 作用 |
| --- | --- |
| `URI` | 模块导入路径，点分层级（如 `MyThings.Panels`） |
| `VERSION` | 模块版本（Major.Minor） |
| `QML_FILES` | 模块的 .qml / .js 文件（会做 qmlcachegen 预编译） |
| `SOURCES` | C++ 源文件（带 `QML_ELEMENT` 的类型自动导出） |
| `RESOURCES` | 模块资源（图片等，进 Qt 资源系统） |
| `IMPORTS` / `DEPENDENCIES` | 模块间依赖（QML 层 / 仅 C++ 层） |
| `IMPORT_PATH` | 告诉构建工具去哪找依赖模块 |

其余都是进阶场景：`NO_PLUGIN` 系列控制插件生成，`ENABLE_TYPE_COMPILER` 启用 qmltc（把 QML 编译成 C++），都有合理默认值。

### 2.3 生成物

构建后模块目录里的关键产物：

```
 DrawPanelQuick 构建产物
 ├─ qmldir                          ← 模块定义（URI、类型表、插件名）
 ├─ DrawPanelQuick.qmltypes         ← 类型信息（Qt Creator 代码提示靠它）
 ├─ DrawPanelQuickplugin.dll        ← 插件本体
 └─ *_qmltyperegistrations.cpp      ← 自动生成的类型注册代码
```

## 3. C++ 类型导出到 QML

Qt6 的方式：类上加 `QML_ELEMENT` 宏，源文件挂进模块的 `SOURCES`，类型自动注册：

```cpp
// MyPainter.h
#pragma once
#include <QQuickItem>
#include <QQmlEngine>   // QML_ELEMENT 宏在这里

class MyPainter : public QQuickItem
{
    Q_OBJECT
    QML_ELEMENT                     // 导出到所属模块，类型名 = 类名
    Q_PROPERTY(int penWidth READ penWidth WRITE setPenWidth NOTIFY penWidthChanged)

public:
    explicit MyPainter(QQuickItem *parent = nullptr);
    int penWidth() const { return m_penWidth; }
    void setPenWidth(int w);

signals:
    void penWidthChanged();

private:
    int m_penWidth = 2;
};
```

```cmake
qt_add_qml_module(DrawPanelQuick
    URI DrawPanelQuick
    QML_FILES DrawPanelControl.qml
    SOURCES MyPainter.h MyPainter.cpp     # 带 QML_ELEMENT 的类挂这里
)
```

QML 里直接用：

```qml
import DrawPanelQuick

MyPainter { penWidth: 4 }
```

导出宏速查表：

| 宏 | 作用 |
| --- | --- |
| `QML_ELEMENT` | 导出为可创建类型（名 = 类名） |
| `QML_NAMED_ELEMENT(X)` | 导出但 QML 里叫 X |
| `QML_SINGLETON` | 导出为单例 |
| `QML_UNCREATABLE` | 不可在 QML 创建（只作类型/枚举载体） |
| `QML_ANONYMOUS` | 匿名导出（只能被同模块使用） |
| `QML_FOREIGN` | 把外部已有类型包装进模块 |

为什么宏方式优于旧式 `qmlRegisterType<>()`：**注册信息进了 qmltypes，工具链可见**——qmllint 能静态检查、qmlcachegen 能预编译、Qt Creator 有代码提示；手写注册对这一切都是黑盒。旧写法在模块机制下不再推荐。

两个配套注意：

- 宏依赖自动生成的注册代码，target 需开 `AUTOMOC`（`qt_standard_project_setup()` 默认已开）；
- 类型继承或使用了其它模块的 C++ 类型时，在 `DEPENDENCIES` 里声明，否则 qmllint 会报错。

## 4. 程序入口与 import 查找

### 4.1 loadFromModule

Qt6 推荐的程序入口：

```cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);

    QQmlApplicationEngine engine;
    QObject::connect(&engine, &QQmlApplicationEngine::objectCreationFailed,
                     &app, []() { QCoreApplication::exit(-1); },
                     Qt::QueuedConnection);

    engine.loadFromModule("appQuickDrawPanel", "Main");
    return app.exec();
}
```

`loadFromModule(uri, typeName)`（Qt 6.5+）：到 import 路径里找 URI 对应的模块，实例化其中的类型——等同 QML 里 `import appQuickDrawPanel` 后 `Main { }`。`objectCreationFailed` 信号的连接是 Qt6 模板工程的标准写法：主界面创建失败立即退出并给出错误，而不是静默留下一个空程序。

### 4.2 import 的查找顺序

QML 引擎解析 `import URI` 时，把 URI 的点换成 `/`，依次在 import 路径里找 `qmldir`：

```
import DrawPanelQuick
        │  点替换为斜杠 → DrawPanelQuick
        ▼
按顺序查找 DrawPanelQuick/qmldir：
┌─────────────────────────────────────────────┐
│ 1. qrc:/qt/qml/          （默认资源前缀）    │
│ 2. exe 所在目录                             │
│ 3. qt.conf 指定的 QmlImports 路径           │
│ 4. engine.addImportPath() 添加的路径        │
│ 5. 环境变量 QML_IMPORT_PATH 指定的路径      │
└─────────────────────────────────────────────┘
```

编译进资源的模块（`qrc:/qt/qml/...`）天然可见，零配置。静态构建时没有插件 dll 可动态加载，`qt_add_qml_module()` 会在配置期扫描 import 自动建立链接；个别被链接器丢掉的插件可用 `Q_IMPORT_QML_PLUGIN(...)` 宏强制引入。

## 5. 资源文件

Qt6 的资源写法与模块是配套的：

```cmake
# 主程序资源：现代签名，不再需要手写 .qrc
qt_add_resources(app "images"
    PREFIX "/images"
    FILES logo.png banner.png
)
# 代码里用 qrc:/images/logo.png 访问
```

模块的资源走 `RESOURCES` 关键字。它们的去向是**双写**（以下已经 Qt 6.8.3 最小工程实测验证）：

```
qt_add_qml_module(item URI item RESOURCES pic.png QML_FILES Main.qml)
        │
        ├─▶ ① 编译进 Qt 资源系统
        │      qrc:/qt/qml/item/pic.png
        │      （路径 = RESOURCE_PREFIX 默认 /qt/qml + URI target path）
        │
        └─▶ ② 复制到磁盘上的模块输出目录
               build/item/：qmldir + Main.qml + pic.png + 插件库
               （供模块以文件形式加载时使用）
```

运行时默认用哪份？自动生成的 `qmldir` 里有一行 `prefer :/qt/qml/item/`——**引擎优先加载资源里的那份**，磁盘副本是文件形态加载（部署、import 路径指向构建目录）时的兜底。所以在构建输出目录里看到图片躺在模块目录中，并不矛盾：那是双写的第二份。

三种引用方式对照：

```
 ├─ 模块内 qml：  source: "pic.png"        ← 相对路径，引擎自动补全 ★
 ├─ 模块外/C++：  "qrc:/qt/qml/item/pic.png"
 └─ 本地文件：    "file:///./pic.png"
```

模块内引用同模块资源直接写文件名即可——这是模块自包含的体现：资源跟着模块走，主程序零感知。

特大资源（视频、大图集——生成的中间 C++ 源码可能数百 MB，编译器吃不消）用 `qt_add_big_resources()` 或 `BIG_RESOURCES` 选项，它直接生成目标文件绕过编译器限制。

## 6. 实例：DrawPanelQuick 模块

把上面所有点串起来的真实工程结构——主程序以子项目方式引入模块：

```cmake
# 主程序 CMakeLists.txt（节选）
qt_add_executable(appQuickDrawPanel main.cpp)

add_subdirectory(DrawPanelQuick)            # 引入模块子项目

qt_add_qml_module(appQuickDrawPanel
    URI appQuickDrawPanel
    VERSION 1.0
    QML_FILES Main.qml
)

target_link_libraries(appQuickDrawPanel
    PRIVATE Qt6::Quick DrawPanelQuick)      # 链接模块 backing 库
```

```cmake
# 模块 CMakeLists.txt（节选）
qt_add_library(DrawPanelQuick SHARED DrawPanelQuick.cpp DrawPanelQuick.h)

qt_add_qml_module(DrawPanelQuick
    URI DrawPanelQuick
    VERSION 1.0
    QML_FILES DrawPanelControl.qml
    SOURCES DrawPanelQuick.cpp DrawPanelQuick.h   # 内含 QML_ELEMENT 类型
)

target_link_libraries(DrawPanelQuick PRIVATE Qt6::Quick)
```

QML 中使用——import 后模块内类型以别名前缀使用：

```qml
import QtQuick
import QtQuick.Layouts
import DrawPanelQuick 1.0 as Jie

Window {
    width: 640; height: 480; visible: true
    ColumnLayout {
        anchors.fill: parent
        Jie.DrawPanelControl {
            drawPanel: drawPanel
            Layout.preferredHeight: 100
            Layout.fillWidth: true
        }
        Jie.DrawPanelQuick {
            id: drawPanel
            Layout.fillHeight: true
            Layout.fillWidth: true
        }
    }
}
```

注意主程序链接了 backing 库后，按 §2.1 的关系图，插件标记为 optional、运行时不再加载——启动即所得。

## 7. 小结

```
 Qt6 QML 模块化全流程
 ┌──────────────────────┐   ┌──────────────────────┐
 │ 1. 写模块             │   │ 2. 主程序引入         │
 │ qt_add_qml_module()  │──▶│ add_subdirectory()   │
 │ QML_FILES / SOURCES  │   │ target_link_libraries│
 │ RESOURCES            │   └──────────┬───────────┘
 └──────────────────────┘              ▼
 ┌──────────────────────┐   ┌──────────────────────┐
 │ 4. 入口加载           │   │ 3. QML 中使用        │
 │ loadFromModule(URI,  │◀──│ import URI as 别名   │
 │   "Main")            │   │ 别名.类型 { }        │
 └──────────────────────┘   └──────────────────────┘
```

一句话：**先以模块为单元组织 QML 功能（qt_add_qml_module），主程序 add_subdirectory 引入并链接，QML 里 import 使用，入口用 loadFromModule 加载主界面**——这就是 Qt6 推荐的 QML 工程组织方式。
