# P1-08 Qt 数据库

> 本文基于 **Qt 6.8.3**。Qt SQL 模块用法不难，难的是线程——本篇的核心是
> 一条官方红线。完整的工程封装案例（LocalDbService + Worker）见 P3-02；
> 多线程模式的基础见 P1-03。

## 1. Qt SQL 模块的三层结构

先说一个和 Qt 其它模块不同的特点：`QSqlDatabase`、`QSqlQuery`、`QSqlError` 这些类**没有继承 QObject**——没有信号槽，它们是纯粹的值类型 / 资源句柄类（呼应 P1-01：不是所有 Qt 类都是"基类公民"）。

整个模块分三层理解：

```
┌────────────────────────────────────────────────────┐
│ 模型层    QSqlQueryModel / QSqlTableModel          │ ← 直接喂给视图（见 P1-11）
├────────────────────────────────────────────────────┤
│ SQL 层    QSqlQuery                                │ ← 手写 SQL：exec / prepare / bindValue
├────────────────────────────────────────────────────┤
│ 驱动层    QSqlDatabase ──▶ QSqlDriver（插件 DLL）   │ ← 连接管理 + 具体数据库驱动
└────────────────────────────────────────────────────┘
```

`QSqlDatabase::addDatabase()` 只是"登记"一个驱动，真正干活的是底层以**插件**形式存在的驱动库（`sqldrivers` 目录下的 dll——正是 P1-06 讲的高级插件）。查看当前可用的驱动：

```cpp
qDebug() << QSqlDatabase::drivers();
// 典型输出：("QSQLITE", "QODBC", "QPSQL")
```

注意官方预编译包**不带 MySQL 驱动**（`QMYSQL`），需要自行编译——见 P3-05。

## 2. 线程亲和：最重要的红线

这是整个 Qt SQL 模块**最容易踩、后果最严重**的一条规则。Qt 官方文档的原话：

> 连接只能在创建它的线程中使用。不支持在线程之间移动连接或从不同线程创建查询。

为什么是红线？连接内部持有驱动分配的句柄（socket、SQLite 文件句柄等），这些句柄大多不是线程安全的；多线程同时操作同一条连接，轻则数据错乱，重则直接崩溃。

```
 ✘ 错误：连接跨线程共享          ✔ 正确：连接不出子线程
 主线程 ──┐                     主线程 ── 调用/结果（QueuedConnection）
          ├─▶ 同一条连接 ◀── 子线程            ↕
                                    子线程 Worker 独占连接 ★
 （多个线程碰同一个句柄 = 赌命）      （连接创建/使用/销毁全程同线程）
```

**Qt 6.8 新增**：`QSqlDatabase::moveToThread()` 可以把连接整体移动到另一个线程——前提是该连接上没有任何存活的 `QSqlQuery`。这是 6.8 才有的一条退路，稳妥的做法依然是"谁创建谁用"。

UI 程序里 SQL 常常是慢操作（网络库、大批量写入），直接在主线程执行会卡界面。正确姿势就是 P1-03 的"包装对象 + Worker"模式在数据库场景的直接应用：

```
主线程                          子线程（DbThread）
┌──────────────────────┐        ┌────────────────────────┐
│ 业务代码              │        │ XxxDbWorker            │
│    │                 │        │  ├─ QSqlDatabase _db   │ ← 连接在此创建
│    ▼                 │ 排队   │  ├─ open() / SQL 执行  │
│ XxxDbService ────────┼───────▶│  └─ QSqlQuery（局部）  │
│ （主线程包装对象）     │ invoke│                        │
│    ▲                 │ Method└───────────┬────────────┘
│    │ 回调（QueuedConnection 回 qApp）      │
│    └─────────────────┴───────────────────┘
```

要点：**连接和 `QSqlQuery` 永远不离开 Worker**；跨线程传递的只有纯数据（参数和结果记录）。完整封装实现（含 init 排队、连接名管理、销毁顺序、错误语义化）见 **P3-02**。

## 3. 基本操作速查

以下示例为讲清 API，直接在同一函数内使用连接；实际工程里请放到上面的 Worker 子线程中。

### 打开连接

```cpp
QSqlDatabase db = QSqlDatabase::addDatabase(QStringLiteral("QSQLITE"),
                                            QStringLiteral("my_conn"));
db.setDatabaseName(QStringLiteral("data/classroom.db"));  // SQLite：库文件路径
if (!db.open()) {
    qWarning() << "open failed:" << db.lastError().text();
}
```

SQLite 的 `databaseName` 就是文件路径（不存在会自动创建）；网络数据库则还要 `setHostName()` / `setPort()` / `setUserName()` / `setPassword()`。

### exec / prepare / bindValue

一次性语句直接 `exec`；带参数的语句**务必用占位符绑定**——既防 SQL 注入又避免转义错误：

```cpp
QSqlQuery query(db);
query.prepare(QStringLiteral(
    "INSERT INTO t_class_roster (class_model_id, student_name, seat_number) "
    "VALUES (?, ?, ?)"));
query.addBindValue(classModelId);   // 按占位符顺序依次绑定
query.addBindValue(name);
query.addBindValue(seat);
if (!query.exec())
    qWarning() << query.lastError().text();
```

同一条语句反复执行时（如批量插入），用 `bindValue(0, ...)` 按下标重绑即可复用 prepare 结果，比每条重新 prepare 快得多。也支持 `:name` 命名占位符。

### 读取结果

```cpp
query.exec(QStringLiteral("SELECT id, student_name FROM t_class_roster"));
while (query.next()) {
    int id = query.value(0).toInt();            // value() 返回 QVariant
    QString name = query.value(1).toString();
}
```

### 事务三段式

批量写必须包事务，任一失败回滚整批：

```cpp
if (!db.transaction()) { /* 报错返回 */ }
// ... 若干条 exec ...
if (/* 某条失败 */) {
    db.rollback();   // 全部撤销
} else if (!db.commit()) {
    db.rollback();   // commit 失败也要兜底回滚
}
```

### 排查错误：lastError 的三层信息

```cpp
QSqlError err = query.lastError();
qWarning() << err.text()            // 综合描述（可直接给用户看）
           << err.databaseText()    // 数据库返回的原文
           << err.driverText()      // 驱动层的说明
           << err.nativeErrorCode();// 数据库原生错误码（如 SQLite 主键冲突 "1555"/"19"）
```

## 4. 常见坑

```
 坑 1：同名 addDatabase 会替换旧连接
 坑 2：removeDatabase 时还有存活对象 → 资源泄漏
 坑 3：SQLite 多线程多连接写同一文件 → SQLITE_BUSY
 坑 4：SQLite 默认不开外键，级联删除静默失效
 坑 5：事务提交时挂着活动查询 → commit/rollback 失败
 坑 6：把 QSqlDatabase 存成跨线程共享成员 → 踩红线
```

逐条展开：

**1. 同名 addDatabase 会替换旧连接。** 用同名再调 `addDatabase()`，新连接会**移除并替换**旧连接；不传连接名时替换的是默认连接。多模块共用进程时，给连接起固定唯一名（如 `"app_local_db"`），不要抢默认连接。

**2. removeDatabase 时不能有存活的对象。** 该连接上不能还有打开的查询，否则资源泄漏。正确姿势是让 `QSqlDatabase` 和 `QSqlQuery` 都先出作用域：

```cpp
{
    QSqlDatabase db = QSqlDatabase::database(QStringLiteral("sales"));
    QSqlQuery query(db);
    query.exec(...);
}   // db 与 query 均已析构
QSqlDatabase::removeDatabase(QStringLiteral("sales"));
```

更省心的做法（P3-02 封装采用的）：连接是 Worker 成员，全程固定连接名，不 remove，随 Worker 析构自然收尾。

**3. SQLite 的多线程限制。** SQLite 默认串行化模式下同一时刻只允许一个写事务，多线程各开各的连接写同一文件会撞 `SQLITE_BUSY`。"一个连接 + 一个专属线程"的模型天然规避——所有写操作在子线程事件循环里本来就是串行的。

**4. SQLite 默认不开外键。** 级联删除（`ON DELETE CASCADE`）依赖外键开关，必须在每条连接上显式执行一次：

```cpp
QSqlQuery q(db);
q.exec(QStringLiteral("PRAGMA foreign_keys=ON"));
```

**5. 事务里还挂着活动查询。** 某些数据库上存在活动的 SELECT 查询时 `commit()` / `rollback()` 会失败。提交前对不再使用的查询调 `query.finish()`。

**6. 不要把 QSqlDatabase 存成"跨线程共享"的成员。** 它是句柄式值类型，拷贝的是同一连接；在哪个线程拷贝、在哪个线程用，都受线程亲和约束。跨线程要传的是**数据和结果**，不是连接。

## 5. 小结

```
 本文要点回顾
  ├─ 三层：驱动层（QSqlDatabase）→ SQL 层（QSqlQuery）
  │        → 模型层（QSqlTableModel，对接视图）
  ├─ 核心类不继承 QObject：值类型/句柄，无信号槽
  ├─ 红线：连接只在创建它的线程可用（6.8 新增
  │   moveToThread 退路，但仍推荐"谁创建谁用"）
  ├─ 工程形态：主线程包装对象 + 子线程 Worker 独占连接
  ├─ 写 SQL：prepare + 占位符绑定；批量写事务三段式；
  │          排查看 lastError 三层文本
  └─ 连接名要唯一固定；SQLite 记得开外键
```
