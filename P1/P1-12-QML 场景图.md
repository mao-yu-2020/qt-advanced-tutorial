# P1-12 QML 场景图

> 本文基于 **Qt 6.8.3**。QML 为什么流畅？答案在它底层的渲染架构——场景图
> （Scene Graph）。本篇讲清它的工作原理和自定义渲染的三条路径；
> mpv 视频渲染进 QML 的完整实战见 P3-04。

## 1. 从"画"到"搭场景"

P1-09 说过 Widget 和 QML 渲染管线不同，这里展开。Widget 是**即时模式**：每次重绘都重新执行 `paintEvent()`，用 QPainter 当场画一遍。QML 是**保留模式**：Item 不是"画出来的"，而是被翻译成一棵**节点树**交给 GPU——

```
 即时模式（Widget）                 保留模式（QML 场景图）
 ┌──────────────┐                 ┌──────────────┐
 │ paintEvent() │                 │ Item 树       │
 │ 每帧重新画    │                 └──────┬───────┘
 └──────────────┘                        ▼ 引擎翻译
                                   ┌──────────────┐
                                   │ QSGNode 节点树│
                                   │（保留在显存侧）│
                                   └──────┬───────┘
                                          ▼ 渲染线程批量提交
                                        GPU 上屏
```

保留模式的好处：节点树建好后**只有变化的部分才更新**，GPU 直接消费结构化节点（矩形、纹理、变换），动画合成都在渲染线程完成——这就是 QML 动画流畅的根因。

## 2. 渲染管线：两条线程的同步舞

Qt Quick 默认用两条线程渲染：**GUI 线程**跑 QML 逻辑（事件、绑定、动画），**渲染线程**消费节点树。两者通过一个**同步点**交接：

```
        GUI 线程                    渲染线程
  ┌───────────────┐         ┌───────────────────┐
  │ 处理事件、动画   │         │ 等待同步点……        │
  │ 执行 QML 逻辑   │         │                   │
  └──────┬────────┘         └───────────────────┘
         │ update() 触发
         ▼
  ┌───────────────┐  同步   ┌───────────────────┐
  │ ★ GUI 线程阻塞 │───────▶│ updatePaintNode() │
  │ 等待渲染完成   │  点    │ 遍历节点树并渲染     │
  └───────────────┘         └─────────┬─────────┘
         │ 恢复执行                      │ 交换缓冲上屏
         ▼                            ▼
```

三条必须记住的纪律：

1. **`updatePaintNode()` 在渲染线程被调用**（不是 GUI 线程）。调用期间 GUI 线程阻塞（同步点），所以函数里可以安全读取 Item 的状态——但**别做耗时操作**，它直接卡住整个界面；
2. **同步点结束后两线程并行**：GUI 线程恢复执行时渲染线程还在画。节点用到的数据要么在同步点内拷贝好，要么保证线程安全；
3. **节点所有权归场景图**：`updatePaintNode()` 返回的 QSGNode 由场景图管理，典型写法是"判空创建、否则复用"，不要每帧 new。

## 3. updatePaintNode：自定义绘制的入口

`QQuickItem` 派生类的自定义绘制入口（`QQuickPaintedItem` 亦同）：

```cpp
QSGNode *UserSG_Paint::updatePaintNode(QSGNode *oldNode,
                                       QQuickItem::UpdatePaintNodeData *)
{
    if (!oldNode)                       // 首次调用：创建节点
        oldNode = new QSGSimpleRectNode();

    auto *node = static_cast<QSGSimpleRectNode*>(oldNode);
    node->setRect(boundingRect());      // 复用节点，只更新属性
    node->setColor(m_color);
    return oldNode;
}
```

机制要点：

- 返回非 nullptr → 场景图直接用该节点渲染；返回 nullptr（`QQuickPaintedItem` 场景下）→ 回退到 `paint()` 的 QPainter 路径；
- 首次调用 `oldNode` 为 nullptr——借此判断创建时机；之后每帧传入上次返回的节点，**复用而非重建**；
- 节点树可嵌套：QSGNode 可以有子节点，随父节点一起按深度优先遍历渲染——QML 里一个普通 Item（背景矩形 + 文本）在场景图里就是这样一棵小树：

```
              ┌──────────────────┐
              │  QSGRootNode（根） │
              └────────┬─────────┘
           ┌───────────┼───────────┐
           ▼           ▼           ▼
     ┌──────────┐ ┌─────────┐ ┌──────────┐
     │ 矩形节点   │ │ 文本节点  │ │ 自定义节点  │
     │(背景/边框) │ │(文字内容) │ │(你的绘制)  │
     └──────────┘ └─────────┘ └────┬─────┘
                              ┌────┴────┐
                              ▼         ▼
                        ┌──────────┐ ┌──────────┐
                        │ 子节点 A   │ │ 子节点 B   │
                        └──────────┘ └──────────┘
        渲染时从根节点深度优先遍历，子节点随父节点一起绘制
```

## 4. 自定义渲染的三条路径

"我要在 QML 里画自己的东西"，按内容来源分三条路：

```
 路径一：QQuickPaintedItem::paint()
   ┌────────────┐  QPainter  ┌─────────┐  上传纹理  ┌────────┐
   │ GUI 线程绘制 │─────────▶│ 软件光栅/FBO│────────▶│ 场景图节点│
   └────────────┘            └─────────┘           └────────┘
   写法最简单，性能一般

 路径二：updatePaintNode() 返回自定义 QSGNode
   ┌────────────┐  同步点   ┌──────────────────┐
   │ GUI 线程    │─────────▶│ 渲染线程：构建/更新 │
   │（此时被阻塞）│          │ QSGNode 直接渲染   │
   └────────────┘          └──────────────────┘
   无中间纹理拷贝，性能最高，官方推荐

 路径三：第三方引擎自产画面（如 mpv）
   ┌──────────┐  OpenGL  ┌──────┐  挂进  ┌────────┐
   │ 外部引擎  │─────────▶│ FBO/纹理│─────▶│ 场景图节点│
   │ 自产画面  │          └──────┘       └────────┘
   引擎自己渲染，Qt 只负责"贴上去"
```

选型表：

| 方式 | 适用场景 | 性能 | 上手难度 |
| --- | --- | --- | --- |
| `paint()`（QPainter） | 简单 2D、低频重绘 | 一般（软件光栅 + 纹理上传） | 最低 |
| `updatePaintNode()` 场景图节点 | 高频自定义图形、复杂绘制 | 高（直接产出 GPU 节点） | 中（要懂渲染线程模型） |
| 第三方引擎 + FBO 集成 | 视频/游戏引擎等外部渲染源 | 高（引擎直渲 FBO） | 高（GL 上下文与线程） |

一句话：**自己画图形用场景图节点，别人产画面用 FBO 集成**。两条路的交汇点是同一个——最终都要变成场景图里的节点/纹理才能上屏。

### 关于路径三的一个关键认知

熟悉 Widgets 的人会问：视频嵌入不能把 widget 的 `winId()` 交给第三方库吗（如 mpv 的 wid 嵌入）？纯 Widgets 程序可以，**QML 里不行**——回到 P1-09 的窗口模型：QML 只有一个原生窗口，Item 没有句柄可交。所以唯一的路是让引擎把画面渲染成 OpenGL 纹理/FBO，再挂进场景图。Qt 为此准备了 `QQuickFramebufferObject`（内部就是 FBO + 纹理节点的现成封装），它的 `render()` 保证在渲染线程执行且 GL 上下文已 current——这正是外部引擎渲染 API 的硬性要求，二者天然契合。完整的 mpv 集成实现（中间 FBO + blit 填充模式、帧驱动重绘链路）见 **P3-04**。

## 5. 小结

```
 本文要点回顾
  ├─ QML = 保留模式渲染：Item → QSGNode 树 → 渲染线程 → GPU
  ├─ GUI/渲染两线程经同步点交接；updatePaintNode 跑在
  │   渲染线程，禁耗时操作
  ├─ 节点归场景图所有：判空创建、逐帧复用
  ├─ 自定义渲染三路径：paint() / 场景图节点 / FBO 集成
  └─ QML Item 无窗口句柄：外部渲染只能走纹理进场景图
```
