# P1-00 前言

> 本教程基于 **Qt 6.8.3** 编写。

## 为什么写这套教程

C++ 是一门强大的语言，但用"裸"C++ 写应用，你会很快撞上四面墙：对象之间怎么通信而不耦合？耗时任务怎么不卡界面？运行时怎么知道一个类有什么方法和属性？界面、数据、网络这些设施从哪来？

Qt 的价值，恰恰是它把这些"软实力"补齐了：

```
              Qt 为 C++ 补上的能力拼图
 ┌──────────────────────────────────────────────┐
 │  信号与槽      ── 对象间通信，天然解耦         │
 │  元对象系统    ── 给 C++ 加上"反射"            │
 │  事件循环      ── 一切异步机制的发动机         │
 │  对象树        ── 树形所有权，内存管理有章法   │
 │  线程设施      ── QThread / 线程池 / 队列连接  │
 │  应用套件      ── JSON / 数据库 / 网络 / 界面  │
 └──────────────────────────────────────────────┘
```

问题在于：Qt 官方文档擅长讲"这个类有哪些函数"，却很少把这些能力串成体系讲——为什么信号槽是解耦的？事件循环和线程是什么关系？对象树为什么能管好内存？**这些架构级的"为什么"，正是这套教程要回答的问题。**

教程的内容来自笔者学习 Qt 的过程和真实项目的积累：有机制原理的梳理，有 Qt 源码的剖析，也有项目里反复验证过的实践模式（Worker 线程模型、异步接口、日志与数据库封装、QML 渲染等）。写下来，是希望把这些散落的经验整理成一条可以循着走的路。

## 适合谁读

本教程**不是入门书**。它假设你已经：

- 写过基本的 Qt 程序（Widgets 或 QML 小程序均可）；
- 知道信号槽、布局、`qmake/CMake` 是怎么回事；
- 想从"会用"走向"懂原理、能设计"。

如果你在写代码时产生过这些疑问——"异步编程到底该怎么做？""模块之间怎么解耦？""线程安全靠什么保证？""对象关系与内存安全怎么设计？"——那你就是这套教程的读者。

## 教程的结构：三层

```
 ┌────────────────────────────────────────────┐
 │ P1 主线教程                                 │
 │   机制与思想，按学习顺序编排                 │
 │   讲"是什么、怎么想、怎么用"                 │
 ├────────────────────────────────────────────┤
 │ P2 深入原理                                 │
 │   Qt 源码剖析，讲"底层怎么实现的"            │
 ├────────────────────────────────────────────┤
 │ P3 项目实战                                 │
 │   真实项目完整案例，讲"工程里怎么封装的"      │
 └────────────────────────────────────────────┘
```

主线是必读路径；主线中涉及源码实现和完整案例的地方，会用"进阶指引"链到 P2/P3 对应篇目——想深挖时再过去，不打断主线节奏。

## 阅读路线

```
 基石线（必读，顺序不能乱）
   P1-01 QObject 与元对象系统
     └─▶ P1-02 事件循环与线程模型
           └─▶ P1-03 QThread 与多线程实践

 工程能力线（可按需选读）
   P1-04 日志 → P1-05 调试与开发效率 → P1-06 插件
     → P1-07 国际化 → P1-08 数据库

 QML 线（建议按序）
   P1-09 Widget 与 QML 选型 → P1-10 Qt6 模块系统
     → P1-11 模型与视图 → P1-12 QML 场景图
     → P1-13 QML 事件处理 → P1-14 QML 对象所有权与 GC

 平台线（独立）
   P1-15 Qt Android 开发
```

基石线是全套教程的地基：QObject、事件循环、线程这三篇建立的词汇和心智模型，后面每一篇都会用到。工程能力线各篇相对独立，用到什么读什么。QML 线内部有依赖，建议按序读完。

## 一些约定

- 文中所有代码以 **Qt 6.8.3 + C++17 + CMake** 为准；
- 流程、结构、对比一律配 ASCII 示意图，图随文走；

- 文中标 ★ 的位置是必须记住的红线或关键结论。
