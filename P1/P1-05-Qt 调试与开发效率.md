# P1-05 Qt 调试与开发效率

> 本文基于 **Qt 6.8.3**。进阶开发和入门开发的分水岭，往往不在"会不会用 API"，
> 而在调试与排查的效率。本篇讲三件效率利器：调试 Qt 源码本身、一个经典的
> 性能排查案例、国内镜像加速。

## 1. 调试 Qt 源码本身

### 为什么需要

读 P2 的源码剖析篇时，光看代码是"静态"的；而调试器能让你"动态"地走进 Qt 内部——断点落在 `doActivate()` 里，亲眼看着信号如何遍历连接、参数如何拷贝排队。学原理，这一步的价值无可替代。日常排查也一样：很多"灵异问题"的线索就藏在 Qt 内部的调用栈里。

### 配置流程

只需两步：**安装时勾选源码 → Qt Creator 配置路径映射**。

```
  ① 安装 Qt 时勾选源码组件
          │
          ▼
  ② Qt Creator → 首选项 → 调试器
     添加源码目录映射
          │
          ▼
  ③ 断点可直接步入 Qt 内部函数
```

**第一步：下载源码。** 运行 Qt 目录下的维护工具 `MaintenanceTool.exe`，在"添加或移除组件"里勾选 **Sources** 组件下载。源码会落到 `Qt/6.8.3/Src/` 目录下。

**第二步：配置源码路径映射。** 打开 Qt Creator 的 **首选项 → 调试器（Debugger）→ 概要（General）**，在源码路径映射（Source Path Mapping）里添加一条映射——调试符号里记录的是 Qt 构建机上的路径，要把它指到本机的真实源码目录：

```
  ┌────────────────────────────────────────┐
  │  调试信息中的路径        本机源码路径     │
  │  /work/build/qt/... ──▶ C:/Qt/6.8.3/   │
  │                         Src/...        │
  └────────────────────────────────────────┘
        ★ 路径对应上，断点才能落到源码行
```

**完成验证。** 在自己的项目里打个断点，单步步入（Step Into）一个 Qt 函数——能走进 `.cpp` 实现、看到局部变量，就说明映射生效了。

## 2. 排查案例：QTableWidget 卡顿

这是一个真实高频的性能坑，也是"如何定位性能问题"的样板。

### 现象

`QTableWidget` 在添加或修改数据时卡顿严重，数据量越大越明显，界面明显掉帧。

### 定位

先想一个问题：**增改一条数据，应该是 O(1) 的事，为什么会越来越卡？** 说明每次增改都触发了与数据总量相关的工作。检查表格配置，发现标题头设成了自动计算列宽：

```cpp
ui->tableWidget->horizontalHeader()->setSectionResizeMode(
    QHeaderView::ResizeToContents);
```

根源用一张图说明：

```
  添加/修改一条数据
        │
        ▼
  ┌──────────────────────────┐
  │ 遍历【整个表格】所有单元格  │ ← 每改一次就全量重算一次
  │ 逐个计算合适的列宽         │    数据越多越卡，O(n²) 噩梦 ★
  └──────────────────────────┘
```

`ResizeToContents` 的含义是"列宽由内容决定"——所以每次内容变化，它都要遍历全表单元格重算列宽。n 条数据每条触发一次 O(n) 全表扫描，总复杂度 O(n²)，几千行就卡得没法用了。

### 结论与正确姿势

**实际开发中切勿对数据会动态增改的表格使用 `ResizeToContents`**。改用：

```
 setSectionResizeMode 选型
  ├─ Stretch      ── 均分拉伸，列宽随窗口自适应（推荐默认）
  ├─ Interactive  ── 固定宽度，用户可拖拽调整
  └─ ResizeToContents ── 仅限静态小表（几十行以内、
                         初始化后不再变动）
```

### 方法论沉淀

这个案例的排查路径值得记住：**"随数据量线性/平方变差" → 找与总量相关的隐藏循环**。Qt 里同类陷阱还有不少（如 `QListWidget` 的逐行操作未关 `updatesEnabled`、模型视图里频繁触发 `layoutChanged`），思路通用。

## 3. 国内镜像源加速

Qt 在线安装器和维护工具默认连官方源，国内下载缓慢。命令行加 `--mirror` 参数即可切换镜像：

```
  默认路径                          镜像路径
  安装器 ──▶ 官方源（海外，慢）      安装器 ──mirror──▶ 国内镜像（快）
```

**常用国内源：**

```plain
- 中国科学技术大学   https://mirrors.ustc.edu.cn/qtproject/
- 清华大学           https://mirrors.tuna.tsinghua.edu.cn/qt/
- 北京理工大学       http://mirror.bit.edu.cn/qtproject/
- 南京大学           https://mirror.nju.edu.cn/qt/
```

**使用方式**（在线安装器和 `MaintenanceTool.exe` 通用）：

```plain
// 命令格式
[cmd] --mirror [URL]

// 示例：用南京大学镜像启动在线安装器
qt-unified-windows-x64-4.8.1-online.exe --mirror https://mirror.nju.edu.cn/qt

// 示例：用镜像源启动维护工具（添加/移除组件）
.\MaintenanceTool.exe --mirror https://mirror.nju.edu.cn/qt
```

一句话经验：装 Qt、加组件、更新，凡是MaintenanceTool 出面的事，都带上 `--mirror`。
